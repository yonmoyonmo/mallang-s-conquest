# 말랑이의 정복 화면·아트 기획

이 문서는 첫 완성판에 필요한 화면 흐름과 아트 제작 목록을 정의한다. 세부 전투 규칙은
`game_design.md`, 파일과 코드 관리 방식은 `project_guidelines.md`를 기준으로 한다.
실제 그림 작업용 파일명과 체크리스트는 `pixel_art_checklist.md`에서 관리한다.

## 1. 화면 설계 원칙

- 모바일 세로 화면 하나만 우선 완성한다.
- 모든 래스터 자산은 픽셀아트로 제작하고 최근접 보간과 정수 배율을 사용한다.
- 한 화면에서 가장 중요한 행동은 하나만 강조한다.
- 라이벌 캐릭터가 패턴의 성격과 전술을 설명하게 한다.
- 패턴 미리보기는 별도 그림 대신 실제 시뮬레이션 데이터로 그린다.
- 스테이지 카드와 대화 초상은 대표 일러스트를 잘라 재사용한다.
- 생명 셀과 점령지는 스킨과 무관하게 플레이어·적 진영을 즉시 구분할 수 있어야 한다.
- 첫 완성판에서는 화면 전환과 작은 효과를 코드로 처리하고 프레임 애니메이션 제작을 줄인다.

## 2. 전체 화면 흐름

```text
시작 화면
└── 메인 메뉴
    ├── 라이벌전
    │   └── 스테이지 선택
    │       └── 라이벌 상세·전투 준비
    │           ├── 덱·스킨 편성
    │           └── 전투
    │               └── 결과·해금
    │                   ├── 재도전
    │                   ├── 스테이지 선택
    │                   └── 라이벌 앨범
    ├── 자유 점령전
    │   └── 자유 게임 설정
    │       ├── 덱·스킨 편성
    │       └── 전투 → 결과
    ├── 수집함
    │   ├── 라이벌 앨범
    │   ├── 패턴 도감
    │   └── 스킨 목록
    └── 설정·크레딧
```

튜토리얼은 별도 메뉴로 만들지 않고 첫 라이벌전의 화면 안내와 전투 오버레이로 제공한다.

## 3. 화면 목록

### S01. 시작 화면

목적: 게임의 첫인상을 전달하고 저장 데이터를 불러온다.

- 게임 제목과 대표 말랑이 또는 셀 군집 연출을 포함한 시작 배경
- `화면을 눌러 시작` 버튼
- 버전 표기
- 최초 실행 시에만 이용 언어 또는 필수 안내 표시

### S02. 메인 메뉴

목적: 세 가지 핵심 활동으로 이동한다.

- 라이벌전
- 자유 점령전
- 수집함
- 설정
- 현재 해금 패턴 수와 격파한 라이벌 수
- 마지막으로 장착한 말랑이·점령 셀 스킨 미리보기

### S03. 스테이지 선택

목적: 록맨식으로 라이벌 8명을 자유롭게 고른다.

- 바깥 8칸에 일반 라이벌, 중앙에 최종 라이벌을 둔 `3×3` 카드 배치
- 라이벌 얼굴 크롭, 이름, 대표 색상과 대표 패턴 아이콘
- 미격파, 격파 완료와 최종 스테이지 잠금 상태
- 최초 승리 보상 표시
- 격파한 라이벌 수와 현재 말랑력

최종 라이벌 카드는 일반 라이벌 8명을 모두 격파하기 전까지 잠금 상태로 표시한다.

### S04. 라이벌 상세·전투 준비

목적: 상대 특성과 보상을 이해하고 전투를 시작한다.

- 라이벌 얼굴 또는 상반신 크롭
- 이름과 전투 전 소개글
- 대표 패턴과 적 덱 성향
- 전장 규모, 라운드 수와 양측 말랑력
- 최초 승리 보상: 패턴, 전체 일러스트, 말랑이 스킨, 점령 셀 스킨
- 현재 플레이어 덱과 장착 스킨 요약
- `편성 변경`, `도전` 버튼

### S05. 덱·스킨 편성

목적: 전투에 사용할 네 패턴과 두 종류의 스킨을 고른다.

`패턴 덱` 탭:

- 덱 슬롯 4개
- 해금한 패턴 목록
- 패턴 이름, 비용, 역할과 최초 배치 형태
- 약 5세대 변화 미리보기
- 덱 중복 패턴은 허용하지 않음

`꾸미기` 탭:

- 말랑이 스킨 슬롯
- 점령 셀 스킨 슬롯
- 해금·잠금 스킨 목록
- 전장 위 조합 미리보기
- 라이벌에게서 한 쌍으로 얻은 스킨도 서로 섞어 장착 가능

### S06. 전투

목적: 패턴을 배치하고 진화를 관찰한다.

- 상단: 라운드, 영토 점수와 남은 말랑력
- 중앙: 생명층과 영토층을 표시하는 전장
- 하단 한 행: 편성한 패턴 4개, 시계방향 회전, 마지막 배치 취소와 진화 시작
- 네 패턴은 순환하지 않고 각각의 버튼을 직접 눌러 선택
- 회전 버튼은 시계방향 화살표와 현재 각도를 함께 표시
- 진화 시작, 회전과 배치 취소는 `24×24` 픽셀아트 아이콘 사용
- 배치 예정 위치의 반투명 미리보기
- 라이벌의 작은 얼굴과 짧은 반응 문구
- 진화 세대 진행 표시

전장 규모는 전투 진입 전에 확정하므로 전투 화면에는 전장 선택 버튼을 두지 않는다.

### S07. 결과·해금

목적: 결과와 최초 승리 보상을 명확하게 전달한다.

- 승리, 패배 또는 무승부
- 양측 최종 점령 칸과 점령률
- 사용한 덱
- 최고 기록 갱신 여부
- 최초 승리 시 보상 순차 공개
  - 대표 패턴
  - 전체 라이벌 일러스트
  - 라이벌 말랑이 스킨
  - 라이벌 점령 셀 스킨
- `재도전`, `스테이지 선택`, `앨범에서 보기` 버튼

패배와 재도전에는 입장 비용이나 불이익을 두지 않는다.

### S08. 자유 게임 설정

목적: 해금한 콘텐츠를 원하는 조건으로 시험한다.

- 전장 규모: 소형, 중형, 대형
- 규모에 따라 고정되는 라운드 수
- 라운드 말랑력
- 격파한 라이벌 또는 랜덤 상대
- 덱·스킨 편성 진입
- `자유 점령전 시작` 버튼

자유 점령전 결과는 해금과 성장에 영향을 주지 않는다.

### S09. 수집함

목적: 획득한 콘텐츠를 다시 감상하고 자유 게임으로 연결한다.

`라이벌 앨범` 탭:

- 9명의 잠금·해금 카드
- 전체 일러스트
- 전투 전 소개와 승리 후 기록
- 대표 패턴과 최고 점령률

`패턴 도감` 탭:

- 12종의 잠금·해금 상태
- 실제 패턴 이름, 역할, 비용과 배치 형태
- 자동 재생되는 짧은 진화 미리보기

`스킨` 탭:

- 말랑이 스킨과 점령 셀 스킨 목록
- 획득 출처
- 장착과 자유 게임 이동

### S10. 설정·크레딧

목적: 필수 환경 설정과 출처 정보를 제공한다.

- 음악, 효과음과 햅틱 설정
- 진화 속도 설정
- 언어
- 크레딧과 라이선스
- 저장 데이터 초기화

광고, 계정, 상점과 인앱 결제 화면은 만들지 않는다.

## 4. 아트 제작 목록

첫 완성판의 신규 제작량은 **라이벌 일러스트 9장, 말랑이 스킨 10종, 점령 셀 스킨
10종, 앱 아이콘 1개와 공용 배경 2개**를 기준으로 한다. 기능 아이콘 약
18종과 테마 문양 10종은 단색 벡터 또는 게임 데이터에서 파생해 제작 부담을 줄인다.

### A. 라이벌 캐릭터

| 자산 | 수량 | 용도 | 제작 방식 |
| --- | ---: | --- | --- |
| 라이벌 대표 일러스트 | 9 | 상세 화면, 앨범, 결과 보상 | 캐릭터별 신규 제작 |
| 스테이지 카드 얼굴 크롭 | 9 | `3×3` 선택 카드 | 대표 일러스트에서 자동 크롭 |
| 대화용 상반신 크롭 | 9 | 전투 준비와 반응 문구 | 대표 일러스트에서 자동 크롭 |
| 잠금 실루엣 | 9 | 미해금 앨범 카드 | 대표 일러스트에서 자동 생성 |

대표 일러스트만 실제 신규 제작 대상이며 나머지는 같은 원본에서 파생한다.

### B. 말랑이·영토 테마

기본 테마 1개와 라이벌 테마 9개를 합쳐 총 10개 테마를 만든다.

| 자산 | 수량 | 용도 | 필수 조건 |
| --- | ---: | --- | --- |
| 살아 있는 말랑이 스킨 | 10 | 생명 셀 내부 표현 | 작은 크기에서도 실루엣 식별 |
| 점령 셀 스킨 | 10 | 영토층의 바닥 무늬 | 반복 배치 시 경계가 튀지 않음 |
| 테마 대표 색상 | 10세트 | 카드, UI 강조와 미리보기 | 플레이어·적 진영색과 분리 |
| 테마 문양 | 10 | 보상 카드와 스킨 목록 | 대표 패턴 형태에서 파생 가능 |

각 라이벌 최초 승리 보상은 해당 라이벌의 말랑이 스킨과 점령 셀 스킨 한 쌍이다. 획득은
한 번에 하지만 두 스킨은 별도로 장착할 수 있다.

진영 구분은 스킨 고유색에만 의존하지 않는다.

- 플레이어와 적에게 고정된 외곽선 또는 광택 방향을 사용한다.
- 점령 셀에는 진영색 틴트와 테마 무늬를 함께 적용한다.
- 양쪽이 같은 스킨을 사용해도 구분되어야 한다.

### C. 공용 UI

| 자산 | 수량 | 비고 |
| --- | ---: | --- |
| 앱 아이콘 | 1 | 작은 크기 식별성 우선 |
| 공용 배경 | 2 | 시작 화면, 메뉴·수집 화면 |
| 패널·버튼 스타일 | 1세트 | 가능하면 Godot StyleBox로 구성 |
| 기능 아이콘 | 약 19 | 홈, 뒤로, 설정, 덱, 스킨, 회전, 취소, 반전, 진화, 잠금 등 |
| 한글 UI 글꼴 | 1패밀리 | Regular와 Bold 굵기, 라이선스 기록 |

### D. 전투 효과

다음 효과는 신규 프레임 그림보다 파티클, 셰이더와 도형 애니메이션으로 우선 제작한다.

- 패턴 배치
- 셀 탄생
- 셀 사망
- 영토 점령과 탈환
- 양 진영 동률 상쇄
- 잘못된 위치 또는 말랑력 부족
- 최초 승리 보상 해금

### E. 별도 제작하지 않는 항목

- 12종 패턴 아이콘: 실제 셀 좌표로 자동 렌더링
- 패턴 진화 미리보기: 실제 시뮬레이션을 축소 재생
- 전장 격자: 코드로 그리기
- 소형·중형·대형 배경: 같은 배경과 격자를 크기에 맞게 배치
- 카드용 얼굴과 대화 초상: 대표 일러스트에서 크롭
- 잠금 실루엣: 대표 일러스트의 마스크로 생성

## 5. 제작 규격

### 공통 픽셀 규칙

- 게임의 논리 화면은 `540×960`이며 세로 `9:16`을 기준으로 한다.
- 데스크톱·에디터 테스트 창은 `1080×1920`으로 열어 논리 화면을 정확히 2배로 표시한다.
- 원본 픽셀 하나가 화면에서 `1×`, `2×`, `3×`처럼 정수 배율로 보이게 배치한다.
- PNG는 보간 없이 가져오고 필터와 밉맵을 끈다. 회전은 패턴 좌표처럼 코드로 처리할 수 있는
  항목에만 사용하며, 픽셀 그림 자체를 임의 각도로 회전하지 않는다.
- 화면 비율이 긴 기기에서는 배경을 확장하되 핵심 UI와 캐릭터는 중앙 `540×960` 안전 영역
  안에 둔다.
- 그림 파일에 글자를 넣지 않는다. 한글과 숫자는 UI 글꼴로 별도 렌더링한다.

정확한 원본 캔버스는 다음 표를 기준으로 한다. 화면에서 더 크게 필요하면 같은 원본을 최근접
정수 배율로 확대한다.

| 자산 | 원본 캔버스 | 형식 | 비고 |
| --- | ---: | --- | --- |
| 라이벌 전체 일러스트 | `180×240` | 투명 PNG | 세로 3:4, 캐릭터 한 명 |
| 라이벌 카드 크롭 | `72×72` | 런타임 크롭 | 별도 제작하지 않음 |
| 라이벌 대화 크롭 | `96×96` | 런타임 크롭 | 별도 제작하지 않음 |
| 시작·메뉴 배경 | `270×480` | PNG | 화면에서 2배 확대 |
| 말랑이 스킨 | `16×16` | 투명 PNG | 한 셀용 |
| 점령 셀 스킨 | `16×16` | PNG 또는 마스크 | 상하좌우 반복 가능 |
| 테마 문양·패턴 표식 | `24×24` | 투명 PNG | 보상과 카드용 |
| 공용 기능 아이콘 | `16×16`, `24×24` | 투명 PNG | 두 크기가 필요할 때 각각 손질 |
| 앱 아이콘 마스터 | `256×256` | PNG | 제출본은 최근접 4배로 출력 |

라이벌 원본에서 카드 초상은 `(54, 12)`부터 `72×72`, 대화 상반신은 `(42, 8)`부터
`96×96` 영역을 사용한다. 얼굴과 주요 특징이 두 영역에 모두 들어오도록 러프 단계부터
확인한다.

### 대표 일러스트

- 세로 `3:4` 비율
- 원본 캔버스: `180×240`
- 캐릭터와 배경을 분리하거나 투명 배경 원본을 보관
- 얼굴이 상단 중앙 안전 영역에 오도록 구성
- 카드 크롭, 상반신 크롭과 전체 화면에서 모두 사용할 수 있어야 함
- 글자와 UI 프레임을 그림에 직접 넣지 않음

### 말랑이 스킨

- 정사각형 원본 `16×16`
- 투명 배경
- 셀 하나가 작아져도 알아볼 수 있도록 큰 형태와 단순한 명암 사용
- 기본 맥동은 코드 애니메이션으로 처리

### 점령 셀 스킨

- 정사각형 반복 무늬 `16×16`
- 이음매 없는 타일 또는 중앙 문양 마스크
- 진영색을 코드에서 입힐 수 있도록 무채색 마스크 원본 보관
- 높은 불투명도로 생명 셀보다 눈에 띄지 않게 함

### UI 아이콘

- 투명 PNG 원본
- 기본 작업 크기 `16×16` 또는 `24×24`
- 한 픽셀 선 굵기와 제한된 팔레트를 공통으로 사용
- 의미를 글자만으로 표현하지 않음

## 6. 파일 배치 계획

실제 자산이 생길 때만 다음 폴더를 만든다.

```text
res://art/
├── art_catalog.gd         # 원본 크기, 자산 ID와 교체 경로
├── characters/            # 라이벌 대표 일러스트
├── themes/
│   ├── mallang/           # 살아 있는 셀 스킨
│   └── territory/         # 점령 셀 스킨
├── ui/                    # 앱 아이콘, 기능 아이콘과 공용 장식
├── backgrounds/
└── effects/
```

코드의 `PixelArtSlot`에는 자산 ID와 원본 해상도가 표시된다. 완성된 PNG를
`art_catalog.gd`에 적힌 경로와 이름으로 놓으면 슬롯이 자동으로 읽는다. 라이벌 파일은
우선 `rival_01.png`부터 `rival_09.png`, 기본 테마 파일은 `default.png`로 명명한다.

원본 작업 파일과 사용권 정보는 각 자산과 가까운 위치에 기록한다. 게임에는 실제로 사용하는
출력본만 포함하고 불필요한 중간 파일은 넣지 않는다.
