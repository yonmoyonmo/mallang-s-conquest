# 전투 메카닉 PoC 구현 계획

이 문서는 **말랑이의 정복(Mallang's Conquest)** 첫 플레이 가능 버전의 구현 계획이다.
세부 코드 규칙과 디렉터리 원칙은 [프로젝트 관리 규범](project_guidelines.md)을 따른다.

- 작성일: 2026-10-14
- 대상 엔진: Godot 4.7, GDScript, 2D
- 대상 플랫폼: iOS 우선, Android 이식 가능 구조
- 렌더러: Compatibility
- 화면 방향: 세로
- 목표: 연속 터치, 증식, 포위, 연쇄 제거 자체가 재미있는지 검증

## 현재 구현 상태

2026-10-14 기준으로 첫 수직 슬라이스 구현을 완료했다.

- Compatibility 렌더러와 `540×960` 세로 기준 화면
- 배열 이중 버퍼 기반 결정론적 시뮬레이션
- 터치 생성, 한 세대 두께의 방사형 파동, 수명과 정체 붕괴
- 동시 증식 의도와 국지적 다수결 충돌
- 무작위 AI 터치와 예고 표시
- 외곽 전장 축소와 원인별 사망 이벤트
- 단색 일괄 렌더링, 셀 수·시간 UI, 승패와 재시작
- 마우스 및 모바일 단일 터치 입력
- 외부 테스트 프레임워크 없는 헤드리스 시뮬레이션 검증

다음 작업은 기능 추가가 아니라 실제 플레이를 통한 규칙 수치 튜닝과 iPhone 실기 검증이다.

실행과 테스트:

```sh
/Applications/Godot.app/Contents/MacOS/Godot --path .
/Applications/Godot.app/Contents/MacOS/Godot \
  --headless --path . --script res://tests/test_battle_simulation.gd
```

## 1. 성공 조건

이 PoC는 다음 질문에 실제 플레이로 답할 수 있어야 한다.

1. 빈칸을 빠르게 연속 터치하는 행위가 즉각적이고 즐거운가?
2. 한 번의 터치에서 시작된 증식 계보를 눈으로 추적할 수 있는가?
3. 적 주변을 두드려 수적 우위를 만들고 밀어내는 과정이 직관적인가?
4. 세포 수명과 정체 소멸이 다음 터치를 위한 빈칸을 충분히 만드는가?
5. 마지막 세포를 둘러싼 전멸전의 공방이 재미있는가?
6. 전장 축소가 교착을 해소하면서도 납득 가능한가?
7. AI가 플레이어와 같은 규칙으로 싸운다고 느껴지는가?
8. 한 판의 길이와 손가락 피로가 반복 플레이에 적절한가?

PoC의 목적은 기능 수를 늘리는 것이 아니라 위 질문에 답하는 것이다.

## 2. 구현 범위

첫 플레이 가능 버전에 포함한다.

- 하나의 빈 전장
- 세로 화면 기준 `36×64` 내외의 논리 격자
- 플레이어의 빈칸 터치
- 적 AI의 무작위 가상 터치와 간단한 예고 표시
- 양 진영에 완전히 동일한 생성·증식·충돌 규칙
- 터치마다 상·우·하·좌 중 2~4개 방향을 무작위 선택하는 방사형 파동
- 다음 세대를 만든 이전 세대가 사라지는 한 세대 두께의 전선
- 세포 수명과 정체 계보 소멸
- 동일 세대 상태에 기반한 국지적 다수결 충돌
- 전멸전
- 시간에 따른 외곽 전장 축소
- 단색 도형 기반 렌더링
- 승리·패배·무승부 표시와 즉시 재시작
- 모바일 터치와 데스크톱 마우스 입력
- 고정 난수 시드를 이용한 재현 가능한 전투

## 3. 범위 밖

다음 기능은 코어 재미가 확인된 뒤 별도 단계에서 다룬다.

- 직선형, 분기형을 포함한 추가 증식 패턴
- 점령전과 전장 템플릿 조합
- 전투 후 보상과 영구 성장
- 능력치 배분, 스킬 해금과 장착
- 전투 중 패시브 및 능동 스킬
- 최종 세계관과 완성 아트
- 스프라이트 애니메이션, 사운드, 햅틱, 화면 흔들림
- `MultiMeshInstance2D`, 전용 셰이더, 효과 풀을 이용한 최종 최적화
- 멀티터치

전투 중 레벨업이나 무작위 강화 선택은 이후 버전에도 도입하지 않는 것이 현재 기획 원칙이다.

## 4. 최초 규칙 가설

아래 수치는 완성 사양이 아니라 첫 플레이 테스트를 위한 시작점이다. 모두 설정 데이터로
분리해 코드 수정 없이 바꿀 수 있게 한다.

| 항목 | 최초값 | 비고 |
| --- | ---: | --- |
| 격자 크기 | `36×64` | 실제 기기 가독성에 따라 조정 |
| 논리 속도 | 초당 `10`틱 | 목표 범위 8~12틱 |
| 화면 목표 | `60fps` | 논리 틱과 분리 |
| 증식 이웃 | 상·하·좌·우 4칸 | 방사형의 최초 단순화 |
| 방사 팔 수 | 터치마다 `2~4개` | 선택 방향은 계보의 모든 후손이 상속 |
| 파동 두께 | `1세대` | 최초 터치점에서 바깥쪽으로만 진행하고 이전 세대는 소멸 |
| 다수결 범위 | 충돌 칸 주변 8칸 | 중심 칸 포함 여부는 테스트로 확정 |
| 동률 판정 | 시드 기반 무작위 | 재현 가능해야 함 |
| 최대 수명 | 약 15~20틱 | 패턴 수명으로 이동 예정 |
| 정체 유예 | 약 8~12틱 | 경고 후 붕괴 |
| 축소 시작 | 약 30초 | 한 판 길이에 따라 조정 |
| 축소 간격 | 약 5초마다 1열 | 외곽부터 중앙 방향 |

다수결에서 중심 칸을 포함할지, 공격 진입 수를 별도 가중할지 등 기획상 열려 있는 세부는
테스트를 가능하게 하는 가장 단순한 규칙으로 먼저 구현하고 플레이 결과와 함께 확정한다.

## 5. 한 틱의 처리 순서

선후공 불공정을 막기 위해 한 틱은 반드시 다음 순서로 실행한다.

1. 플레이어와 AI의 터치 명령을 입력 큐에서 꺼낸다.
2. 현재 유효 영역의 빈칸에 대한 터치만 생성 후보로 반영한다.
3. 입력이 반영된 동일한 현재 상태를 기준으로 양 진영의 증식 의도를 각각 계산한다.
4. 모든 목표 칸의 양 진영 증식 의도를 합쳐 충돌 위치를 찾는다.
5. 각 충돌을 동일한 세대 상태의 주변 세포 수로 독립 판정한다.
6. 수명, 정체, 전장 축소에 따른 소멸을 원인별로 기록한다.
7. 다음 상태를 한꺼번에 확정하고 현재 상태와 교체한다.
8. 생성·증식·충돌·사망·축소·승패 이벤트를 렌더러에 전달한다.

렌더링 프레임이나 애니메이션 완료 시점은 이 처리 순서에 영향을 주지 않는다.

## 6. 데이터 모델

셀마다 독립 노드를 만들지 않는다. `BattleState`가 셀 인덱스를 기준으로 한 배열을 소유한다.

```text
faction[index]
lineage_id[index]
pattern[index]
direction[index]
age[index]
generation[index]
cell_state[index]
```

- 현재 상태와 다음 상태를 별도 버퍼로 관리한다.
- 빈칸도 동일한 인덱스에 진영 없음 상태로 표현한다.
- 터치 하나가 새 `lineage_id`를 만들고 모든 후손이 이를 물려받는다.
- 정체 판정은 계보가 마지막으로 새 칸을 얻은 틱을 기준으로 시작한다.
- 전투 사망, 자연 소멸, 정체 붕괴, 경계 소멸을 서로 다른 이벤트로 기록한다.
- 난수 발생은 `BattleSimulation`이 소유한 시드 기반 생성기 한 곳으로 제한한다.

초기 구현에서는 명료성을 우선하되, 셀 객체 수천 개를 매 틱 생성·폐기하는 구조는 피한다.
필요하면 `PackedInt32Array` 등의 병렬 배열로 구성한다.

## 7. 책임 분리

```text
BattleInput ──┐
EnemyTouchAI ─┼──> Battle ──> BattleSimulation ──> SimulationEvent
              │      │               │                    │
              │      └───────────────┴────────────> BattleRenderer
              └────────────────────────────────────> Battle UI
```

### `BattleSimulation`

- 전투 상태, 증식, 충돌, 수명, 정체, 축소와 승패를 계산한다.
- `Node`를 상속하지 않고 화면 및 SceneTree를 참조하지 않는다.
- 동일한 초기 상태, 시드, 입력 기록에 동일한 결과를 반환한다.

### `Battle`

- 논리 틱을 구동하고 입력, AI, 시뮬레이션, 렌더러를 연결한다.
- 게임 규칙을 직접 계산하지 않는다.

### `BattleInput`

- 화면 좌표를 격자 좌표로 변환하고 터치 시도 명령을 만든다.
- 점유 칸 입력에 즉각적인 실패 피드백을 요청할 수 있지만 최종 유효성은 시뮬레이션이
  판정한다.

### `EnemyTouchAI`

- 전투 상태를 바꾸지 않고 플레이어와 동일한 터치 명령만 만든다.
- 최초에는 무작위 빈 공간을 선택하고, 이후 전선 주변 가중치를 별도 조정값으로 실험한다.

### `BattleRenderer`

- 상태와 이벤트를 읽어 단색 도형으로 표시한다.
- `_draw()` 기반의 일괄 렌더링으로 시작한다.
- 논리 틱 사이의 화면 보간은 허용하지만 전투 상태를 변경하지 않는다.

### 단계 2: 결정론적 시뮬레이션

- 시드 기반 난수

완료 기준: 렌더러 없이도 고정 입력의 상태 변화를 검증할 수 있다.

### 단계 3: 충돌과 전투

- 양 진영 증식 의도의 독립 계산
- 세 가지 충돌 상황 검출
- 주변 다수결과 동률 판정
- 전투 사망 이벤트
- 전멸 승패와 동시 전멸 무승부

완료 기준: 처리 순서와 무관하게 같은 틱의 국지전 결과가 같다.

### 단계 4: 플레이 가능한 상대

- 무작위 AI 터치
- AI 터치 위치 예고
- 셀 수와 전투 상태 UI

완료 기준: 사람 대 AI 전멸전을 반복해서 플레이할 수 있다.

- 계보별 정체 감지
- 경고 상태와 지연 붕괴
- 시간 기반 전장 축소

### 단계 6: 손맛 조정과 실기 검증

- 터치 즉시 피드백과 점유 칸 실패 피드백
- 틱 속도, 수명, AI 속도, 축소 시점 조정
- 한 판 길이와 연타 피로 기록
- iPhone에서 터치 누락, 프레임, 발열, 배터리와 가독성 확인

완료 기준: 코어 전투의 재미를 유지·수정·폐기 중 하나로 판단할 플레이 데이터가 있다.

## 10. 검증 시나리오

최소한 다음 경우를 반복 가능하게 확인한다.

- 빈칸 터치는 셀을 만들고 점유 칸 터치는 상태를 바꾸지 않는다.
- 같은 틱에 같은 빈칸으로 들어온 양 진영이 다수결을 수행한다.
- 적 점유 칸으로 증식할 때 직접 터치 피해 없이 충돌이 발생한다.
- 여러 충돌 칸이 서로의 처리 순서에 영향을 주지 않는다.
- 동률 결과는 같은 시드에서 재현된다.
- 최대 수명 소멸은 상대의 전투 처치로 기록되지 않는다.
- 정체 계보는 경고 뒤 제거된다.
- 축소된 영역의 셀은 경계 소멸로 구분된다.
- 한 진영만 0이면 반대 진영이 이기고 양쪽이 0이면 무승부다.
- 재시작 시 이전 전투의 셀, 입력 큐, 타이머와 난수 상태가 남지 않는다.

## 11. 튜닝 기록 원칙

- 조정값 변경 전후에 전투 시드와 핵심 수치를 기록한다.
- 느낌만 적지 않고 한 판 시간, 초당 터치 수, 최대 셀 수, 역전 횟수 등 관찰 가능한 값과
  함께 기록한다.
- 한 번에 여러 핵심 변수를 바꾸지 않는다.
- 재미를 만들지 못하는 규칙은 구조를 복잡하게 유지한 채 보정하지 않고 제거하거나
  단순화한다.
- 실제 병목이 측정되기 전에는 렌더링 구조를 고도화하지 않는다.

## 12. PoC 종료 판단

다음 중 하나의 결론과 근거를 남기면 PoC가 종료된 것으로 본다.

1. **유지:** 현재 코어가 재미있어 연출과 패턴을 확장한다.
2. **수정:** 재미의 가능성은 있으나 충돌, 수명, 축소 중 특정 규칙을 재설계한다.
3. **폐기:** 연타와 포위가 반복 플레이할 핵심 재미를 만들지 못한다.

유지 결론이 나온 뒤에만 추가 증식 패턴, 점령전, 전투 후 보상, 성장과 최종 아트를
본격적으로 계획한다.
